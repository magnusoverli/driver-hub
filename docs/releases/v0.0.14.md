Driver Hub is now organised around what you do with it: find a driver in the catalog, download it, set up a device and see whether it works. The side navigation has three entries: **Devices**, **Catalog** and **Settings**.

**Devices** is the home page and replaces Overview and Deployments. Counts at the top (**Needs attention**, **Running**, **Stopped**, **Update available**) filter the list, and a legend explains the four-part status. **Add device** lets you choose a downloaded driver and goes straight to setting it up. On a new site, a checklist leads from connecting Nomad and VideoIPath to the first device. Site problems appear as one notice above the list. Old `/deployments` links redirect to the new pages.

A device page now leads with its status: a headline, the four steps from **Requested** to **VideoIPath**, and what to do next. **Start**, **Stop** and **Update to** *version* are in the header. An **In VideoIPath** panel shows the node ID to look for in Inspect → Devices, with a copy button. The configuration is visible, and **Edit** changes it without changing the driver version, after a Nomad preview. Allocations, version history and scheduler evaluations stay under **Diagnostics**.

The **Catalog** lists each driver once, with its latest version, whether it is on this Hub, and how many devices use it. Each driver has its own page with all its versions and the devices that run it. Importing a local image and building from source are under **Add custom driver**, and **Download history** replaces Activity in the navigation. When published releases cannot be loaded, drivers already on this Hub are still listed.

**Settings** groups its pages: **Site setup** shows site readiness; **Connections** holds Nomad cluster and VideoIPath; **Access** holds Users and API tokens. **Advanced** holds source builds, request timings, the Nomad job options formerly on the Nomad page, and the startup settings. `/settings/manager` redirects there.

The setup dialog now shows **Start the driver right away** next to the required settings. Throughout the interface, Driver Hub says *device*, *set up* and *downloaded* where it said *deployment*, *stage* and *retained*. The API is unchanged.

The VideoIPath endpoint check now includes a disposable `node_id` that matches no deployed device, because VideoIPath matches the driver route only with one present. It still sends no credentials or WebSocket upgrade.
