Driver Hub now reads driver declarations with **schemaVersion 2**, the format the VideoIPath External Drivers repository defines for per-input `url` and `enum` constraints. Every value a device would start with is checked against them, whether you enter it, the site's VideoIPath target supplies it, or it is a default: in the setup form, and again before each start, update and rollback. A driver that would refuse its own configuration, such as a `ws://` endpoint for a release that only accepts `wss://`, is stopped before Nomad runs it, with the reason. Hub tests the cases both repositories agreed on (`test/fixtures/driver-config`). Version 1 declarations work as before.

Each page now holds only what serves its own job:

- **Settings → Site setup** takes over the getting-started checklist, and a new site opens there. Site problems show as one indicator in the top bar instead of on Devices. A missing VideoIPath target is optional, since each device can enter its own connection.
- A device page separates its status from a **Before you start** list: secrets to create, or the external driver to stop. It shows the VideoIPath node ID once, links its driver, and offers rename beside the title. The pinned image, Nomad job and revision are under **Diagnostics**.
- **Add device** opens a page with four steps: driver, device, settings and review. Settings use readable labels, with the input's key in the hint.
- Driver pages open with what the driver needs, how it connects and whether Hub can monitor it. Published drivers are listed by their display name.
- The Nomad and VideoIPath settings are each one form. The Hub download address sits with image distribution; VideoIPath is split into its connection and its driver tokens.
