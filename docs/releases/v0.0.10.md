### Catalog downloads on LAN HTTP

Fixed **Download** failing before it sent a request when Driver Hub was opened over plain HTTP at a LAN address. Both catalog views, source builds, and deployment staging now generate secure UUIDv4 request keys even when the browser does not expose `crypto.randomUUID()`. Retrying an unanswered download reuses its key so the manager can recognize the original operation.

### VideoIPath settings

**Settings → VideoIPath → Save** now reports whether the manager can reach the saved external-driver endpoint, even with no staged drivers. Use **Check again** to retry. The check does not send the saved token or open a driver session; a reachable endpoint does not confirm token validity.

### Passwords and status displays

New local passwords require at least 10 characters, including an uppercase letter and a digit. Existing passwords still work. The UI continues to refresh live status in the background without a ticking “Updated … ago” label.

### Upgrade

Use the `compose.yaml` attached to this release to pin the manager to v0.0.10. Keep the existing data volume and `.env`; if `DRIVER_HUB_IMAGE` is set, update that pin too. Run `docker compose pull` followed by `docker compose up -d`, then reload the browser to pick up the download fix.
