The catalog follows a driver's lifecycle. Each published release shows **Not downloaded**, **Downloading…** or **Downloaded**, with **Download** or **Set up driver** at the end of its row. The table of recent downloads and builds is gone. Instead, a message follows the download or build you started until it finishes or fails, and **Activity** keeps the full history.

Setting up a driver asks for everything the deployment needs up front: a device name, whether it is a new device or replaces an existing driver, and the VideoIPath connection, followed by the driver's required inputs. Only inputs with defaults remain under **Optional settings**. The API still accepts devices without a name.

The device status path no longer shows an **Approval** step that Driver Hub cannot observe. Its last step, **VideoIPath device status**, tells you to check the device in Inspect → Devices and shows the node ID to look for, with a copy button. A release without a control check now shows **No control check provided**.
